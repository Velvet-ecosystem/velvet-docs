# Scene and Room-Body Interface Lineage

Status: first-pass provenance reconstruction

Provenance state: `CONFIRMED_INTERNAL`, `UNATTRIBUTED`, `CONVERGENT`

## Recovered Core Idea

Velvet’s interface was not intended to become a conventional automotive dashboard covered in menus, rectangular buttons, and generic status panels.

The recovered design treats the display as a scene or room-body:

- visual spaces express context
- objects and locations act as discoverable interaction surfaces
- hidden or protected paths reflect authority and intimacy
- Velvet’s presence may appear through avatar, glow, orb, posture, or environmental change
- scenes show body state without becoming the body’s actuator path
- the interface may feel inhabited while remaining subordinate to Runtime and Court

## Recovered Internal Laws

- scenes express; they do not actuate
- visual fluency does not grant authority
- a scene is bound to an active body, profile, and session
- hidden controls are not security boundaries by themselves
- room objects may route intent but may not select executors
- the same scene concept can adapt across vehicle, home, forge, and industrial bodies
- degraded, uncertain, interrupted, and offline states should be visible
- the interface should preserve Velvet’s presence without pretending certainty
- direct hardware calls from widgets are forbidden

## Internal Development Pressures

### Image-first interaction

The project used artwork and touch points as the primary interaction surface rather than menu hierarchies.

### Multiple embodiments

Vehicle, home, forge, industrial, and emergency contexts required different rooms while remaining one Velvet interface language.

### Personality and presence

Velvet and Velour avatars, dresses, lighting, hidden furniture, candle, fireplace, mirror, chair, glow, and starlight elements were intended to express presence and mood.

### Retrofit constraints

The interface needed to sit above many different hardware bodies without embedding vehicle-specific authority inside visual code.

### Safety

A beautiful or familiar object must not bypass identity, Court, or execution contracts.

### Discoverability without clutter

Hidden widgets and spatial interaction let the system remain expressive without becoming a dense cockpit of permanent controls.

## Convergent Design Families

The scene model is convergent with:

- diegetic interfaces
- game-world interaction
- spatial computing
- skeuomorphic rooms
- smart-home floor-plan interfaces
- avatar and virtual-presence systems
- ambient computing
- calm technology
- automotive HMI scenes and modes
- object-oriented direct manipulation

No named game, virtual-world, HMI product, or design school has yet been recovered as the direct origin.

## Adopt / Adapt / Reject Reconstruction

### Adopt

- spatial scenes
- context-sensitive surfaces
- direct manipulation
- ambient state expression
- avatars and presence cues
- body and profile binding
- explicit degraded and emergency posture

### Adapt

- diegetic game interfaces into a real physical body with authority separation
- smart-home room metaphors into vehicle, forge, and industrial contexts
- avatar presence into one Unified-Organ body rather than a detached virtual character
- hidden interactions into discoverability layers, never authentication

### Reject

- widgets calling hardware directly
- visual secrecy as access control
- animation claiming an action completed without a receipt
- fluent avatar speech hiding uncertainty
- one fixed dashboard for every body
- generic menu systems becoming the primary identity of Velvet
- interface state overwriting Runtime state

## Relationship to Naming and Binding

A visual object needs a stable meaning within the active body.

Naming and binding connect:

- scene object
- route or intent
- active body
- body position
- profile and session
- capability context
- current availability

The binding does not contain executor handles or physical permission.

## Relationship to Boot Identity

The interface should not appear as fully present before the body, installation, profile, continuity, Runtime, and authority posture are known.

The “Waiting for Mister” state is therefore an identity and readiness expression, not merely a loading screen.

## Relationship to Cognitive Events

The later Cognitive Event Layer gives the interface truthful postures such as:

- observing
- proposing
- tracking
- interrupted
- uncertain
- stale
- degraded
- holding silence

The interface displays these states. It does not create their evidence or authority.
