# Dream State Memory Scheduling Boundary

Memory work runs in three tempos.

## Awake or active

Permit fast retrieval, current-context recall, low-latency owner interaction, and lightweight observation capture. Heavy consolidation and trusted identity changes are refused.

## Quiet, parked, or inactive

Permit local extraction, index building, duplicate cleanup, observation consolidation, archive organization, summarization, and long-running local-model tasks when power and thermal policy allow them.

## Presence required

Doctrine changes, identity changes, trust-boundary changes, module promotion, authority expansion, and permanent memory adoption require verified physical presence and approval.

## Laws

Dream State may prepare proposals and evidence. It does not execute trust-changing decisions. A prepared change remains inert until the presence-required phase approves it. Scheduling decisions record phase, task class, power posture, presence evidence, refusal reason, and receipt ID.
