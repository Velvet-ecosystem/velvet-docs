# Build for the Weak

## Preserved positioning line

> **We built for the weak stuff first. If you think better hardware changes the story, go find out.**

Keep this wording available for later public-facing Velvet material, especially when addressing skepticism about whether the architecture only works on unusually capable hardware.

## Why it matters

Velvet's engineering posture is to prove useful behavior on constrained, old, inexpensive, reused, and imperfect hardware first. More capable hardware should add headroom, throughput, acceleration, storage, and optional capabilities rather than redefine the architecture or make Velvet possible.

The line works because it turns skepticism into an invitation to test the claim. A critic, builder, or adopter can run Velvet on stronger hardware and independently verify whether the same architecture simply gains room to breathe.

## Use with evidence

This line should be used only alongside real demonstrations and test evidence. Suitable proof includes degraded hardware, weak CPUs, old laptops, reused storage, constrained radios, dropped links, reconnect storms, missing peripherals, and other failure/degradation tests.

The message is not that weak hardware is always desirable. The message is that expensive hardware is not a prerequisite for the architecture to exist.
